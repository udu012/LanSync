# 把 LanSync 从云端搬回本地继续维护

## 先说清楚一件事

云端的这次对话，本地是**看不到**的。所以「移交任务」实际上要搬两样东西：

| 搬什么 | 载体 |
|---|---|
| 代码 | `LanSync/` 整个目录（含 `.git`，能看到完整提交历史）|
| 上下文（为什么这么设计、哪里有坑、还差什么）| `AGENTS.md` + 本文件 |

只要这两样在，本地任何一个 AI 助手打开这个文件夹都能无缝接手——因为 `AGENTS.md` 会被自动读取，它比聊天记录更可靠（聊天记录会丢，文件不会）。

---

## 一、下载

从这次的成果卡片里下载这两个文件，放到同一个地方，比如 `E:\AI生成资料库\`：

| 文件 | 大小 | 内容 |
|---|---|---|
| `LanSync-完整交接包.zip` | 约 30MB | 源码仓库（含 git 历史）+ 编译好的 exe/apk + 全部文档 |
| `LanSync-源码.zip` | 约 300KB | 只有源码，想快速看代码或 `git clone` 时用 |

> 只需要第一个。第二个是备选。

## 二、解压到本地

建议路径：`E:\AI生成资料库\LanSync\`

解压后应该是这样：

```
E:\AI生成资料库\LanSync\
├─ AGENTS.md              ← 给 AI 看的，别删
├─ README.md              ← 给你看的，怎么用
├─ server\                ← 电脑端源码（Go）
├─ app\                   ← 手机端源码（Kotlin）
├─ dist\                  ← 编译好的成品
│  ├─ LanSync.exe
│  ├─ LanSync-控制台版.exe
│  └─ LanSync.apk
└─ docs\交接说明.md        ← 本文件
```

**先别急着装环境。** 直接双击 `dist\LanSync.exe` 就能跑，先把功能验一遍，确认能用再谈改代码。

## 三、验一遍（10 分钟）

1. 双击 `dist\LanSync.exe`，防火墙弹窗勾「专用网络」→ 允许
2. 浏览器自动打开看板，记下地址（形如 `http://192.168.1.x:8765`）
3. 手机连同一个 Wi-Fi，浏览器打开这个地址 → 能上传照片 = 电脑端 OK
4. 手机装 `dist\LanSync.apk`（允许未知来源）→ 扫码 → 点「立即同步」
5. 电脑右下角弹「已接收 N 个文件」= 全链路通

哪一步断了记下现象，第 6 节有对照表。

## 四、按需要装环境

| 你想做什么 | 需要装 | 体积 | 难度 |
|---|---|---|---|
| 只用，不改代码 | 什么都不用装 | — | — |
| 改电脑端（界面、同步逻辑） | **Go 1.21+** | 约 200MB | 简单，装完 `go build` 即可 |
| 改手机端 | **Android Studio** | 约 6GB | 中等，首次同步依赖较慢 |

### 装 Go（改电脑端）

1. 下 https://go.dev/dl/ 的 `go1.21.x.windows-amd64.msi`，一路下一步
2. 打开 PowerShell 验证：`go version`
3. 编译：

```powershell
cd E:\AI生成资料库\LanSync\server
go build -trimpath -ldflags "-s -w -H windowsgui" -o ..\dist\LanSync.exe .
```

> 第一次编译会自动下依赖（一个二维码库），需要联网。

### 装 Android Studio（改手机端）

1. 下 https://developer.android.com/studio ，装完启动，让它自动装 SDK（platform 34 + build-tools 34.0.0）
2. `File → Open` 选 `E:\AI生成资料库\LanSync\app` 目录（**不是** LanSync 根目录）
3. 等 Gradle 同步完成（首次 5~15 分钟）
4. 菜单 `Build → Build Bundle(s)/APK(s) → Build APK(s)`
5. 产物在 `app\app\build\outputs\apk\debug\app-debug.apk`

## 五、让本地的 AI 接着干

在本地 WorkBuddy（或任何能读写文件夹的 AI 工具）里，把工作目录设为 `E:\AI生成资料库\LanSync`，然后发这段话：

```
先读 AGENTS.md 和 README.md，了解这个项目。
这是从云端迁移过来的 LanSync 项目，v1.0 已编译通过。
我现在的需求是：____________
注意协议契约在 AGENTS.md 第 4 节，改一端必须同步改另一端。
```

`AGENTS.md` 里已经写清了：目录地图、协议表、9 个已知的坑、已验证和未验证的部分、合理的下一步排序。AI 读完这些，不需要你再复述背景。

**如果你用的是没有自动读 AGENTS.md 的工具**，就把这句话改成「先完整读一遍 AGENTS.md」，或者直接把文件内容贴给它。

## 六、常见问题对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击 exe 没反应 | 正常，它是无窗口程序 | 浏览器开 `http://127.0.0.1:8765`，或看 `lansync.log` |
| 手机打不开看板 | 防火墙 / 不同 Wi-Fi / AP 隔离 | 换控制台版 exe 看日志；路由器关掉「AP 隔离」 |
| 扫码后 App 显示连不上 | 电脑 IP 变了 | 重新扫一次（二维码里的 IP 是启动时探测的） |
| 通知不弹 | Windows 通知设置被关 / 未在 Windows 实测 | 跑 `LanSync.exe -test-toast` 单独验证 |
| 编译报 `go: cannot find module` | 没联网或代理 | 设置 `GOPROXY=https://goproxy.cn,direct` |
| Gradle 同步卡住 | 依赖下载慢 | 在 `app/build.gradle.kts` 的 repositories 里加国内镜像 |

## 七、万一本地环境搞不定

不用推倒重来。云端这个项目目录还在，随时可以回来继续改——你只要把本地改过的文件传回来覆盖即可（或者反过来，把云端的 `server/` `app/` 覆盖到本地）。

两边都保留 `.git` 目录时，用 `git diff` 就能看出差异，不会互相覆盖丢代码。

**一条建议**：如果你打算长期维护，花 5 分钟在本地做一次 `git commit`，之后每次改动都提交。这样任何一次改坏了都能回退，这比任何备份策略都管用。
